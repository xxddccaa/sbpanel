# Constitution — sbpanel 长期工程原则

## 一、项目核心约束
1. **零外部依赖单二进制**：Go 后端仅使用标准库（`go.mod` 无 `require`），`CGO_ENABLED=0` 交叉编译单文件交付；前端 `web/` 使用原生 HTML/CSS/JS 并通过 `//go:embed` 嵌入，不引入构建工具链或外部 CDN。
2. **无桌面 Linux 全环境兼容**：优先适配 `systemd`（沙箱失败自动降级普通 unit），无 `systemd` 或非 root 环境自动降级后台进程与 `~/.local` 布局，不硬性要求 root 或交互桌面。
3. **原子落盘与失败回滚**：状态文件（`state.json`）、生成的 `config.json` 和二进制替换均使用同目录临时文件 + `rename`；导致 `sing-box` 无法启动的变更或内核/面板升级必须自动回滚到上一个可用状态。
4. **外部下载强制校验与隐私脱敏**：下载 `sbpanel` / `sing-box` 发布包必须验证 SHA-256；下载规则集必须检验魔数并通过 `sing-box check`；订阅请求错误必须剥离 URL（避免账号密钥泄露到 UI、状态文件与日志）。
5. **不静默外连**：禁止后台定时轮询 GitHub 检查版本；订阅默认仅手动更新，开启自动更新时必须附带随机抖动（0~25%）。
6. **最小安全边界**：前端严禁使用 `innerHTML` 渲染外部数据；所有写操作接口必须校验 `Sec-Fetch-Site`、`Origin` 与 `X-SBPanel` 请求头；所有接口必须经 `checkHost` 防 DNS 重绑定。

## 二、不可绕过质量底线
1. **禁止新增压制注释**：禁止在代码里新增 `@ts-ignore`、`eslint-disable`、`# noqa`、`# type: ignore`、`//nolint` 等检查屏蔽注释。
2. **禁止留空错误处理或假桩**：禁止新增空 `catch {}`、吞错忽略关键失败路径，或提交未实现的占位假桩（stub/mock 充当生产逻辑）。
3. **禁止删改或跳过测试换绿灯**：修 Bug 或重构时，不能通过删除断言、注释用例或加 `t.Skip` 掩盖失败。
4. **禁止降级规则阈值过检**：不得为让变更通过检查而放宽 `go vet`、`gofmt`、`shellcheck` 或 CI 校验门槛。
5. **禁止溢写未指定文档**：除非用户明确要求，禁止在 `docs/` 或仓库根目录新建总结报告、指南或架构草稿；项目工程真相统一维护在 `.agent-forge/`。
6. **英文 Why 注释规范**：源码注释与 docstring 默认使用英文；只解释反直觉前提、协议约束或并发/平台陷阱（Why），禁止复述代码字面动作（What）或写修改履历式注释。
